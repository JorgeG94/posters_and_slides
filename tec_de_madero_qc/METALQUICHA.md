# Metalquicha — executive summary (from origin/main @ 51a7aa0f2f, 2026-10-06; all numbers from the repo)

- Name: Met'al q'uicha = "girasol" in Huastec/Tének; Huasteca region = where Tec de Madero (Cd. Madero, Tamaulipas) is.
- Open-source QC framework in modern Fortran (2003+, OO). MIT. github.com/JorgeG94/metalquicha, docs metalquicha.readthedocs.io (+FORD API docs). Started 2025 as code for an invited Pacifichem talk.
- Two differentiators: (1) fragmentation as first-class design, any fragment method x any QC method via one interface; (2) own ab initio engine "cenzontle" (bird of 400 voices: HF, DFT, MP2, CC, MCSCF, EFP, SAPT) on top of libfint (all-Fortran port of libcint) -> no C compiler needed.
- Scale: ~155k lines Fortran (52k core, 103k backends) + ~86k lines tests; 2,186 commits; v0.2.0; 168 unit test modules (test-drive); 340 ab initio CPU validation cases + 25 core cases vs PySCF with same basis data (~1e-8 agreement). CI: GitHub Actions build/test, Codecov, fortitude + house linter, docs, nvfortran & LFortran builds. Compilers: gfortran, ifx/ifort, nvfortran, LLVM Flang (partial). Runs on NERSC Perlmutter (A100) and NCI Gadi (Sapphire Rapids).
- Fragmentation: MBE any order w/ per-level distance screening (5-10x speedups), VMFC counterpoise; GMBE (overlapping fragments, inclusion-exclusion, peptides); FMO & EE-MBE (GAMESS FMO model; AFO bond cutting; PIEDA: electrostatics, exchange, CT, dispersion); EFMO; EFP/MAKEFP (GAMESS-format compatible); H capping w/ gradient & Hessian redistribution; method-agnostic (xTB, HF, DFT, MP2, CC...).
- Methods: GFN1/GFN2-xTB (tblite, ALPB/GBSA); RHF/UHF direct/in-core/DF, SOSCF, stability; DFT full ladder via libxc (LDA..meta-GGA, RSH wB97X, CAM-B3LYP, VV10 wB97X-V/wB97M-V/B97M-V, double hybrids B2PLYP); MP2 conv/RI/SCS/SOS; CCSD & CCSD(T) conv & RI, spin-adapted (~16x smaller), open-shell; CASSCF/CASCI, AVAS, ORMAS/RAS, SA-CASSCF; TDHF/TDDFT (TDA & Casida); SAPT0/SAPT2; NEO (quantum protons); CPCM/IEF-PCM 40+ solvents; ECPs (energies); QUAO, charges, bond orders, Fukui.
- Derivatives/workflows: analytic gradients HF, DFT (mGGA, RSH, VV10), MP2 (4 exact/fitted combos), double hybrids, CASSCF/ORMAS; analytic Hessians incl. double hybrids (glycine trimer: replaces 1,962 s semi-numerical Hessian); semi-numerical Hessians over MPI; RRHO thermochem; geometry opt via DL-FIND (L-BFGS; Cartesian/DLC/HDLC) incl. fragmented; Python interface (Python drives on rank 0, Fortran distributes over MPI): pKa/pI, BDE workflows, CREST conformers.
- HPC: hybrid MPI+OpenMP, hierarchy global coordinator -> node coordinators -> workers. GPU: NVIDIA cuEST (HF/DFT energies, gradients, Hessians, whole molecules & every fragment); "terco" in-house GPU engine in standard-parallel Fortran (do concurrent, nvfortran), RI-MP2 runs through it. Profiling: CPU HF integrals 42 s -> 13 s (L-shell kernels); CCSD iterations water hexamer 33 s -> 4.6 s on one 104-core node. Built-in benchmark suite.
- Science: water hexamers, testing Nguyen & Xantheas (JCTC 2026) MBE convergence. VMFC MP2: >99% of correlation contribution is 2-body (aug-cc-pVDZ & aug-cc-pVTZ); alternating higher-order terms without CP are BSSE. 3-body SCF (polarisation) ~ -8.4 kcal/mol, insensitive to CP & basis. Uncorrected CCSD(T), 18 isomers: 3-body correlation more repulsive than MP2 in every isomer by +0.06 to +0.44 kcal/mol (mean +0.23); not yet CP-corrected, VMFC confirmation is next.
- Development: AI-assisted, human-validated: developer designs architecture + pseudocode, LLM implements, developer writes tests, validates physics, reviews; nothing merges without validation vs PySCF/Psi4/GAMESS. Strict style guides, JSON input deck (validated) & JSON output with per-fragment breakdown; Bohr/Hartree internally.
- Roadmap: analytic PCM gradients (pKa in solution); analytic spin-adapted CCSD(T) gradients (water clusters at gold standard); SA-CASSCF gradients all roots + non-adiabatic couplings (excited-state dynamics); relativistic X2C/DKH; broader GPU via terco; code-quality phase.
- Students welcome: project explicitly aims to be accessible with no Fortran/QC background.
